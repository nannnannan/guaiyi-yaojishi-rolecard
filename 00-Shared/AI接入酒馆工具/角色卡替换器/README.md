# 角色卡替换器

把新版本角色卡写入旧卡原头像槽位，保留该槽位的全部聊天记录。替换过程不先删除旧角色卡；新版
世界书确认加载后，精确删除旧卡独占绑定的异名旧世界书。

## 使用

先做只读预检：

```powershell
npm run replace-card -- "《诡异药剂师》v0.4" "新版本\诡异药剂师_v0.5.json" --dry-run
```

确认输出中的目标卡、头像槽位、聊天数量、新卡名和新世界书后，再实际执行：

```powershell
npm run replace-card -- "《诡异药剂师》v0.4" "新版本\诡异药剂师_v0.5.json" `
  --confirm-target "《诡异药剂师》v0.4"
```

支持 `.json` 和 `.png`。加 `--json` 可获得机器可读报告。

## 安全规则

- 实际替换必须提供与旧角色名逐字一致的 `--confirm-target`，否则拒绝写入。
- 新卡名如果已被另一张卡占用，拒绝替换，避免产生同名卡。
- 覆盖前备份旧卡 PNG、全部聊天和相关世界书到
  `backups/card-replace/<旧角色名>-<时间戳>/`。
- 旧世界书名只取旧角色卡的实际绑定字段，不拿内嵌名称猜测删除目标。
- 新卡内嵌世界书会创建或更新；确认新版世界书存在后，才删除异名的旧绑定世界书。
- 新旧世界书同名时只原位更新，不执行删除。
- 旧世界书仍被其他角色卡绑定时，在任何写入和备份前拒绝替换，避免误删共享书。
- 新卡的绑定世界书名与内嵌世界书名不一致时，在写入前拒绝替换。
- 无关世界书不读取为删除目标，也不会被删除。若替换失败，恢复覆盖前的相关世界书快照。
- 覆盖后核对头像槽位、最后聊天指针、每个聊天文件的消息数与 SHA-256、世界书条目、正则和助手脚本。
- 校验失败自动恢复旧卡；自动回滚创建的新世界书仅限本次失败事务新建且覆盖前不存在的书。
- 禁止拿用户正式角色卡做功能测试；写入型测试只允许使用工具生成的唯一临时卡。

## 验证

```powershell
npm run verify-replace
```

该测试会生成带时间戳的临时旧卡、新卡、共享引用保护卡和再升级卡。它先确认共享旧世界书时 dry-run
与实际写入均被阻止且数据零变化，再连续执行两次替换，确认聊天字节指纹不变、上一版世界书被精确
删除、新版世界书创建、无关世界书保留，以及正则/助手脚本更新，最后只删除这批临时数据。
