# 看日志功能说明

本文说明「看酒馆日志」这个功能是怎么做到的：如何让酒馆边运行边把日志写进文件，
以及我怎么读取和分析它。

## 第一步：为什么需要它

酒馆的终端窗口从系统层面读不到（Windows Terminal 的缓冲区拿不到内容），
所以之前只能靠手动复制粘贴。为了让「日志」变成可以主动读取的东西，
需要让酒馆的输出**落盘成文件**。

## 第二步：让酒馆边运行边写日志

关键是启动方式：

```powershell
node server.js 2>&1 | Tee-Object -FilePath $env:TEMP\tavern.log
```

- `node server.js`：正常启动酒馆；
- `2>&1`：把报错输出也合并进来，否则报错不会进文件；
- `| Tee-Object -FilePath ...`：把输出复制一份写到日志文件（终端照常显示，文件同步记录）。

这样酒馆一跑起来，终端里滚动的所有内容都会同步进 `tavern.log`。

## 第三步：我怎么读它

```powershell
Get-Content $env:TEMP\tavern.log -Tail 200          # 看最新 200 行
Select-String -Path $env:TEMP\tavern.log -Pattern 'DeepSeek request|DeepSeek response'   # 只找关键行
```

实际经验：

- 文件正被酒馆写入时（Tee-Object 独占写句柄），用 `Get-Content` 能读，用 `ReadAllText` 会报
  「文件被占用」——所以统一用前者；
- 日志里的中文偶尔乱码，是因为 Tee-Object 写入的编码和读取端不一致，不影响看请求/响应结构；
- 判断问题：日志里**没有** `DeepSeek request` → 请求根本没发出去（查连接）；
  有 request 但回复空 / `...` → 模型端空回复（重试）。

## 第四步：收尾

这套「看日志」功能的完整、跨平台命令见 `提示词监听/README2.md`（Windows 用
`$env:TEMP\tavern.log`，macOS/Linux 用 `/tmp/tavern.log`），它只是 `--capture`
提示词监听的兜底方案。

一句话总结：**不是去偷看终端，而是让酒馆自己把输出写进文件，再读文件——**
这样重启后随时能看，不用再手动复制。
