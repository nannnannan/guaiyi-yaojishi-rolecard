# 酒馆运行时速查（实测版）

> 探测目标：本机 `http://127.0.0.1:8000`
> 实测环境：SillyTavern **1.17.0**（release，gitRevision aa50edcf4）+ Tavern Helper **4.9.1**
> 探测方式：Playwright + Edge 无头连接页面，读取 `window.SillyTavern` / `window.TavernHelper` 实测
> 探测日期：2026-08-03；来源级别：实机（high）；如酒馆升级，请先重跑 `tools/probe.mjs`

## 4. Tavern Helper 4.9.1 页面级包装（实测 typeof = function）

### 世界书（优先使用这组）

```js
TavernHelper.getWorldbookNames()          // 全部世界书名
TavernHelper.getGlobalWorldbookNames()    // 全局世界书
TavernHelper.getCharWorldbookNames()      // 角色世界书 { primary, additional }
TavernHelper.getWorldbook(name)           // 读取；返回「uid 字符串为键」的条目对象
TavernHelper.replaceWorldbook(name, entries)
TavernHelper.updateWorldbookWith(name, updater)
TavernHelper.createWorldbookEntries(name, entries)
TavernHelper.deleteWorldbookEntries(name, uids)
TavernHelper.createWorldbook(name)
```

**实测坑**：`getWorldbook(name)` 的返回值不是 `{name, entries}`，而是
`{ "0": {uid,name,enabled,strategy,position,content,...}, "1": {...} }`（uid 字符串为键）。
读取时遍历 `Object.keys(w)` 过滤含 `content` 的对象即可。
未打开聊天时调用 `getChatWorldbookName()` 会报「目前不支持对非当前聊天调用」。


### 角色卡

## 5. UI 选择器（实测存在）

```js
#send_form textarea    // 输入框（#send_textarea）
#send_but              // 发送按钮
#stop_generating       // 生成中出现的停止按钮
#option_delete_mes     // 内置“删除消息”入口（选择某层后删除该层及以下）
#option_regenerate     // 内置“重新生成”；处理器调用 Generate('regenerate')
#rm_print_characters_block .character_select   // 角色行（.ch_name 是角色名）
```

角色切换：找到 `.character_select` 行（`.ch_name` 文本匹配），点击整行。
发送消息：填 `#send_textarea`，点 `#send_but`；等待生成用
`eventSource.on(GENERATION_ENDED)` + 轮询 `#stop_generating`。

删除与重新生成（SillyTavern 1.17.0、2026-08-04 实机源码核对）：

- 内置批量删除先保存聊天，再发出 `MESSAGE_DELETED`；MVU 可通过该事件回退到剩余末层状态。
- `Generate('regenerate')` 在末条为助手回复时先删除旧回复并发出 `MESSAGE_DELETED`，再生成替代回复；
  末条为用户消息时不删除，直接生成下一条助手回复。
- 世界书文件和条目不会被这两个核心流程直接改写；下一轮命中会按回退后的聊天重新扫描。
- CLI 是短会话：需要对既有聊天操作时，用
  `--character <角色名> --chat-id <聊天ID>` 在同一条命令内定位，不能依赖上一条 `switch`。

角色卡原位替换（同版本实机源码与连续两次临时卡验收）：

- `TavernHelper.importRawCharacter(slotName, pngBytes)`：把 PNG 载荷写入指定头像文件槽位；替换器在
  调用后重新加载页面，并以“原头像文件名 + 新显示名”双重校验是否覆盖成功。
- `TavernHelper.getChatHistoryBrief(name)` + `getChatHistoryDetail(brief)`：替换前备份并指纹化该头像
  槽位的全部聊天；写入后重新读取，逐聊天核对消息数和 SHA-256。
- SillyTavern 核心 `/api/characters/merge-attributes`：按本机 `script.js` 中
  `updateRemoteChatName` 的请求格式持久化最后聊天指针 `{ avatar, chat }`。
- `ctx.convertCharacterBook(characterBook)` + `ctx.saveWorldInfo(name, data, true)`：把角色卡标准的
  `character_book.entries` 转成核心世界书模型并立即保存；不能把原始 Character Book 条目直接传给
  Tavern Helper 的 `createOrReplaceWorldbook`。
- 旧世界书删除目标只取角色记录的 `data.extensions.world`（兼容归一化 `worldbook`），不使用
  `character_book.name` 猜测旧绑定；新版内嵌世界书先按新版名称创建/更新。
- 新旧世界书异名时，确认新版已存在并再次扫描所有角色绑定；旧书仍被其他卡绑定则拒绝删除，否则调用
  `TavernHelper.deleteWorldbook(oldName)` 并轮询确认消失。同名时原位更新、不删除，无关世界书不动。
- 失败回滚恢复覆盖前世界书快照，并仅清理本次失败事务新建、覆盖前不存在的世界书。

## 6. 认证

- 白名单模式开启时页面出现登录表单（DOM 中存在但默认隐藏）。
- 桥接脚本检测到可见登录表单时读取环境变量 `ST_PASSWORD` 填入并提交。
- 本工具不绕过认证、不读取或存储密码。

## 7. 给写卡 AI 的映射

| 需求 | 优先方案 |
|---|---|
| 读聊天 | `chat` 命令 / `ctx.chat`（字段 `mes`） |
| 读/改世界书 | `worldbook` 命令 / `TH.getWorldbook` + `updateWorldbookWith` |
| 读/切角色卡 | `characters` / `switch` 命令 / `TH.getCharacter` |
| 触发生成 | `send --wait` / `ctx.generate` / `TH.generate` |
| 删除末尾消息 | `delete [数量]`（核心 `ctx.deleteMessage` + 保存 + `MESSAGE_DELETED`） |
| 重新生成 | `regenerate`（点击宿主 `#option_regenerate` 并等待 `GENERATION_ENDED`） |
| 保留聊天升级角色卡 | `replace-card`（先 `--dry-run`，实际执行必须 `--confirm-target`） |
| 执行 Slash | `exec` 命令 / `TH.triggerSlash` |
| 订阅事件 | `ctx.eventSource.on(ctx.eventTypes.X)` |
| 需要版本信息 | `TH.getTavernVersion()` / `TH.getTavernHelperVersion()` |
