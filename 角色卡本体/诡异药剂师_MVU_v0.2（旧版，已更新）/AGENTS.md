# 《诡异药剂师：血锯药剂店》v0.2 AI 接手指南

## 适用范围

本文件适用于 `诡异药剂师_MVU_v0.2/` 整个目录。后续 AI 在此项目内分析、修改、扩写、构建或验证角色卡时，必须遵守本指南。

这是一个完整可导入 SillyTavern 的 `chara_card_v3 / 3.0`、MVU Zod 角色卡工程。正式产物为：

`dist/诡异药剂师_血锯药剂店_v0.2.json`

不要直接编辑 `dist/` 中的产物。所有修改应进入 `src/`、`manifest.json`、`contract.json`、`profile.json`、`创作规划.yaml` 或构建工具，再重新打包。

## 权威事实来源

按以下优先级理解项目：

1. 用户在当前任务中的明确要求。
2. `创作规划.yaml`：项目内容范围、人物边界和维护约束的首要事实来源。
3. `contract.json`：必须满足的结构、人物组件矩阵、禁止项和验收条件。
4. `manifest.json`：稳定 ID、版本、源文件映射、运行依赖及交付物。
5. `profile.json`：卡片类型、能力、更新协议和已废弃特性。
6. `src/`：实际维护源码。
7. `dist/`：由源码生成的候选产物，不是编辑源。

如果内容修改会改变既有规划，必须先更新 `创作规划.yaml`，再修改对应源码，最后同步契约或清单。

## 项目目标与内容范围

- 显示名：`《诡异药剂师：血锯药剂店》v0.2`
- 版本：`0.2.0`
- 卡片稳定 ID：`weird-apothecary-blood-saw-shop`
- 世界书稳定 ID：`weird-apothecary-worldbook`
- 原作资料范围：第1章至第21章，从系统觉醒到小小完成夜间牙科治疗及命名。
- 早期事件是可改写的剧情种子，不强制玩家复刻原作顺序或结果。
- v0.1 目录已废弃但必须保留，不得覆盖、迁移或删除。

七名核心角色固定为：

- 左左
- 血锯
- 血衣女士
- 小小
- 人偶夫人
- 爱丽丝
- 黑弦月

所有七人必须具备基础信息、性格调色盘和二次解释。左左、血衣女士、人偶夫人、黑弦月还必须具备三面性。

配角群像固定分为：

- 白日病患与街坊：人皮拾荒者、小宝贝、血娃娃、猪头魔、恶灵血婴、烧死鬼、猎魔人奥卡洛斯。
- 不眠夜异常群像：血肉欺诈者、钢性傀儡、黑夜食腐者。

配角只记录身份、可见特征、行为方式、与林恩的关系和剧情功能，不进入 MVU 七人关系表，不创建隐藏好感或跨事件变量。

## 不可破坏的叙事边界

- 玩家独占20岁林恩的对白、主动动作、选择、判断、记忆和内心。
- AI 不得替林恩补写决定，不得把建议写成玩家已经执行的事实。
- 血锯固定为非恋爱师徒。
- 小小固定为非性伙伴与家人。
- 爱丽丝固定为非性家人。
- 左左只有在形成独立、明确成年的人格与形态后，才可能进入成人关系。
- 黑弦月固定为成年外形、成年心智和自主意志的人偶。
- 未登场角色必须保持 MVU 锁定，不得因世界书存在而提前登场或获得后期认知。
- 成人内容必须建立在明确成年、清晰同意和自然情境上。
- 不得新增战斗、等级、阶位、装备、技能树、库存、货币、商店经济或经营模拟系统。
- 使用玩家宏时优先写 `<user>`，不要在 YAML 条目中使用 `{{user}}`。

## 世界书维护规则

`src/worldbook.json` 是内嵌世界书注册表；正文分散在 `src/prompts/`、`src/characters/` 和 `src/npcs/`。

新增或修改任何世界书条目时：

1. 先在 `创作规划.yaml` 中同步范围、人物或事件变化。
2. 使用稳定、唯一的数字 ID；不要复用其他条目的 ID。
3. 保持现有条目命名前缀：
   - `[核心]`
   - `[角色速览]`
   - `[角色:基础]`
   - `[角色:性格]`
   - `[角色:三面性]`
   - `[角色:二次解释]`
   - `[NPC群像]`
   - `[initvar]`
   - `[mvu_update]`
4. 关键词条目必须使用精确、安全的角色名及已知别名；避免过宽关键词导致无关触发。
5. 新增或修改条目必须同时开启：
   - `extensions.exclude_recursion: true`，对应 SillyTavern 的“不可递归/防止递归”。
   - `extensions.prevent_recursion: true`，对应“防止进一步递归”。
6. 不要把上述规则误写成 `extensions.delay_until_recursion`；“延迟到递归”不是用户要求的开关。
7. 下一次发生世界书内容变更时，至少对所有本次触及的条目应用两个递归开关，并为验证器增加相应检查。
8. 当前已通过真实宿主验收的 v0.2 不因本规则单独重打包，避免让用户为纯维护约束重复导入。

## MVU 数据契约

MVU 根变量保持：

- `元数据`
- `世界`
- `林恩`
- `病例`
- `事件`
- `关系`
- `系统`

`关系`下只能保留七名核心角色键。配角不得加入关系表。

必须保持：

- 玩家年龄为20。
- 卡名与版本为 v0.2 / `0.2.0`。
- 更新协议为 `UpdateVariable.JSONPatch`。
- 同轮更新可独立工作；额外更新模型只是宿主可选项。
- 初始变量、Zod Schema、变量更新规则、变量输出格式和状态栏字段语义一致。
- 不恢复已废弃的 VWD 值—描述对、命令式 MVU 更新或战斗系统。

修改任一变量字段时，必须沿整条链同步检查：

`src/initial_variables.json` → `src/scripts/schema.js` → `src/prompts/mvu_update_rules.md` → `src/prompts/mvu_output_format.md` → `src/ui/status.html` → `contract.json` → `tools/validate.mjs`

## 状态栏兼容经验

状态栏源码是 `src/ui/status.html`，由 `src/regex_scripts.json` 打包为消息内 HTML。

真实宿主曾出现两类误报：

1. 状态栏在 MVU 跨 iframe 注册完成前读取，显示“未检测到 Mvu”。
2. 消息 iframe 未暴露 `waitGlobalInitialized`，显示“酒馆助手未提供 MVU 初始化等待接口”。

实际聊天楼层当时已经包含完整 `stat_data`，因此问题属于状态栏桥接兼容，不是 MVU 核心未运行。

当前实现必须保留多路径读取：

- 从当前或父页面查找 `Mvu.getMvuData`。
- 找不到 Mvu 接口时，从宿主 `SillyTavern` 聊天消息的 `message.variables[swipe_id]` 读取已保存状态。
- 通过 iframe 名称解析当前消息楼层。
- 后台短时查找 Mvu，成功后再订阅变量初始化和更新结束事件。

不要把状态栏退回为只检查 `globalThis.Mvu`，也不要重新强制依赖 `waitGlobalInitialized`。状态栏只能展示已有 MVU 状态，不能建立第二套状态源。

## 修改与构建流程

1. 阅读 `创作规划.yaml`、`contract.json`、`manifest.json` 和目标源码。
2. 检查工作区已有改动，保留用户的无关修改。
3. 内容或范围变化先更新 `创作规划.yaml`。
4. 只编辑维护源码，不手改 `dist`。
5. 对世界书条目应用两个递归开关。
6. 对 MVU 变更执行整链传播。
7. 在本目录运行：

   ```powershell
   npm run check
   ```

8. 要求构建与验证均以退出码0结束，验证结果为 `offline-candidate`。
9. 记录新产物大小和 SHA-256。
10. 只要变更涉及运行时、MVU、脚本、正则或状态栏，就必须在真实 SillyTavern 中重新导入并验收；离线通过不能替代宿主验收。
