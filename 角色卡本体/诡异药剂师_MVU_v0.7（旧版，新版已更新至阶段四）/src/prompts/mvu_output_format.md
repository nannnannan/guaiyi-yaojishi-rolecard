# MVU输出格式

每次回复正文结束后先输出`<StatusPlaceHolderImpl/>`，再在最末尾输出且只输出一个变量块。`Analysis`只写简短事实核对，不展开推理过程；`JSONPatch`必须是合法JSON数组。禁止使用`<setvar>`、YAML、对象合并或省略状态栏占位符；即使宿主预设没有注入角色卡`post_history`占位，本条仍然生效。

事件迁移原子规则：只要修改锚点`状态/收尾`、唯一活跃事件的`事件ID/标题/状态`或近期预兆`事件ID`，`JSONPatch`中必须只用一条`replace /事件`，其`value`为从当前变量复制并完成本轮修改后的完整事件对象。不得拆成多个`/事件/...`子路径操作。前件为取消态时，先核对后件局部依赖与替代入口；不得由状态栏或模型机械推进。完整对象中的`最近结果`必须始终是四字段对象数组。

<UpdateVariable>
<Analysis>
- 核对本轮已明确发生的世界、事件、人物处境与直接关系变化。
- 检查只有一条重大事件活跃，未替林恩补充任何内容。
- 检查完成、变形或取消的事件不残留在唯一活跃事件；取消态没有被机械推进；空活跃事件与空预兆使用标准空对象。
- 检查恶堕值与关系数值变化均有正文言行支撑。
- 时间检查只写“时间格式合规”，不得在`Analysis`中复述任何被禁时间词、日期示例或负例。
</Analysis>
<JSONPatch>
[
  {"op":"replace","path":"/事件/唯一活跃事件/进展","value":"示例：只记录本轮正文已经发生的事件进展"},
  {"op":"replace","path":"/系统/事件通知","value":"示例：E02诊疗已完成并处于收尾活跃态，E03尚未触发"}
]
</JSONPatch>
</UpdateVariable>
