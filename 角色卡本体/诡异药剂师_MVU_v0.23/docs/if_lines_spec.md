# if 线编写规范（v0.23.0 沙盒化）

## 目标

为每个主线事件 E01–E798 编写一份「if 线」参考池（3–30 条「若…」分支），作为林恩偏离原著的合法通道与创作参考，不强制执行，只是池子。

## 文件布局

- 每事件一份独立文件：`src/if_lines/E01_系统觉醒与开店.md`、`src/if_lines/E02_血娃娃上门与找妈妈任务.md` …共 798 份。
- 与 `src/events/E0X…md` 同名同标题，后缀相同（`{事件编号}_{事件标题}.md`）；validator 校验一一对应。
- 打包阶段由 `tools/build.mjs`（或 `tools/pack_if_lines.mjs`）把每份 if_lines 内容**追加**到对应世界书事件条目末尾，以二级标题 `## if线` 呈现；源码仓库中保持独立文件。

## 文件结构（单文件模板）

```
# E0X·{事件标题}·if线

- 若……则……
- 若……则……
- ……（3–30 条）
```

## 编写规则

1. **段名即标题**：统一只有 `# E0X·{事件标题}·if线` 一级标题，分支一律用 `- 若` 开头的 bullet，不再出现「差分/后台推进/原主角偏离反应」等 Z_Y 字眼。
2. **分支条件明确**：每条必须写成 `- 若{林恩具体动作/选择/条件}则{可落地的事件级后果或衔接}`。避免「若玩家做坏事则会很糟」这种空泛句；避免「玩家无法知道」这种旁白。
3. **与变形条件分层**：「变形条件」是事件级收束判定（哪种变化会让事件转为变形），不重复写进 if 线；if 线写的是「局部偏离怎么演」「等价结果有哪些」「不同身份/状态的分支」。if 线前提成立且够大时可以直接引用对应「变形」。
4. **张力定条数**：
   - 高张力事件（手术/告白/契约/亲密/战斗/谈判/救场/背叛/恶堕/主宇宙大事件）：20–30 条
   - 中等张力：10–19 条
   - 低张力余韵/日常：3–9 条（允许短，不硬凑）
5. **字数上限**：单文件 if_lines 内容（不含标题）**≤2000 字符**；字数核验由 `tools/validate-if-lines.mjs` 单独跑。
6. **玩家主权**：绝不写「林恩想到/决定/选择原谅」这类替玩家做决定的语句；林恩动作必须是「若林恩……」的**条件句**起点。
7. **绝对不做**：
   - 不引入 E799 或超出 E01–E798 的事件编号
   - 不出现元数据词汇（第 X 章、阶段几、小总结）
   - 不替已立项的「变形条件/完成条件/取消条件」改字
   - 不把 if 线写成强制流程（没有「必须」「就先」「接着要」）
8. **成人向**：允许涉 NSFW（以M、解咒途径、恶堕调教），但要走「事件事实成立则直白呈现动作/身体反应/过程与结果」口径；不避重、不防御性叠甲、不写免责声明。真实幼年角色（纱奈儿/返幼期星轨/小林恩）禁止性内容；成年存在的幼态外形按成年处理。
9. **衔接明确**：遇到「等价结果」（如不来医院但用配方调配出解药）要写清楚等价路径如何成立；遇到「取消/变形」要写怎么标记与后续影响。
10. **语气**：与现有事件正文一致，白描、陈述式，不用繁文缛节的前缀。

## 校验

- 独立校验：`node tools/validate-if-lines.mjs`
  - 每份 iff_line.md：3 ≤ 分支条数 ≤ 30，内容 ≤ 2000 字符，标题与事件编号严格匹配，不含禁元数据词
- 主 check 不受影响：`npm run check` 仍跑 build + validate + validate-integration；if_lines 由 build 在世界书打包时合并注入。
