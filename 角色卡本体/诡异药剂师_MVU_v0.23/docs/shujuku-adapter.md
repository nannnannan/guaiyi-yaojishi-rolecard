# 诡异药剂师 × 龙血玄黄·数据库（AutoCardUpdater / SP·数据库）适配方案

更新：2026-10-03 · 适用卡体：v0.23.0（E798 全书封箱）· 插件基线：`AlbusKen/shujuku` 1.0.0（manifest `龙血玄黄·数据库 1.0.0`）

> **基线判断**：本卡运行在酒馆默认装有「龙血玄黄·数据库」（AutoCardUpdater）的环境中。卡不打包预设、不绑定数据库代码，由玩家酒馆对插件本体管理。本文件是给**卡维护者**看的内部文档，不是玩家安装手册——玩家只要装卡即可，数据库的事玩家自己处理。

## 数据层划分

| 层 | 拥有者 | 内容 |
|---|---|---|
| **E 锚点**（E01–E798） | 本卡（MVU `事件.锚点状态` + 世界书 EJS） | 原著事件走向参考：主线因果、分支通道、出场人物。它讲「剧本本来要说什么」。 |
| **AM 纪事**（AM0001+） | 数据库（纪要表 + 纪事折叠表） | 玩家实际走过的剧情纪年，由数据库的填表 AI 每轮自动写入。它讲「玩家实际走过了什么」。 |

## 三条仲裁（AI 侧铁律）

1. **E 锚点 > AM 纪事**：剧情对得上 E 锚点时，E 状态变迁（MVU `事件.锚点状态`）是唯一因果事实；AM 是当轮纪事流水，不是裁决。
2. **AM 只记事实**：AM 行只记当轮客观发生（地点 / 在场 / 时间 / 关键词），不判断、不规划、不写「应该」。
3. **AM 引用只引实际编号**：正文 `[AM0003]` 形式的引用只能指实际存在或本轮已被召回助手提示出来的编号，不能凭空编造。

## 为什么不内置预设 / 模板 JSON

- 数据库的模板预设是**玩家侧插件的配置**，由玩家在插件面板上管理。本卡如果交付预设 JSON 并随卡安装：
  - 预设版本与酒馆实际数据库插件版本易失配（插件快速更新，玩家按本卡预设走会偏离插件当前语义）
  - 预设是**全局或聊天级别**，不是角色卡字段——打进卡 JSON 不生效
- 三合一配套正则是**玩家自己的显示层选择**，与要玩的卡类型绑定，不应该被某张卡强制安装

因此本卡不做任何「数据库交付」：玩家在酒馆正常装卡，数据库按它自己的默认预设跑，卡内部的提示词与 regex 只保证**当 AM 召回出现时，AI 能正确理解上下文、引用编号并做到不互写**。

## 常见排查表象（给后续维护者用）

| 症状 | 根因 | 处理方向 |
|---|---|---|
| AI 正文里出现 `[AM0009]` 但酒馆AM表只到AM0003 | AI 凭空编造编号（post_history「十一」红线被越） | post_history 提醒条落实 / 提高该模型的提示词遵循度 |
| 玩家说「AI 忘了前面发生的事」 | 召回助手没关联 / 填表 AI 没写关键词列 | 检查数据库插件的设置（召回助手独立模型是否连上）；卡侧不需要动 |
| 状态栏近期事务和 AM 是一回事吗 | 不是。卡内 MVU `系统.沙盒.近期事务` 是 Schema 已定义的结构化滚动记录，不存 AM 正文 | 见 mvu_update_rules.md「沙盒层」；AM → MVU 指针桥接仍未实现 |
| 玩家关掉数据库插件后看到 `[AM0009]` | 这是正文引用泄漏，不是卡 bug | 玩家自己关掉插件的后果，卡侧拦截不走直给 |
