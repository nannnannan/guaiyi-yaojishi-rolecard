# 长篇原文阶段扩展工作流

用于把小说、剧本或连续剧情资料向后改编一个或多个角色卡版本。目标是可追溯地覆盖原文细节，而不是只做章节摘要。

## 1. 冻结权威链与阶段边界

1. 先读目标项目的 `AGENTS.md`、创作规划、manifest、contract、profile、源码与既有校验脚本，确认“用户要求 → 创作规划 → 契约/清单 → src → dist”的权威链；旧版和 `dist/` 保持只读。
2. 完整浏览已有大总结、小总结、阶段总结，再定位下一阶段在原文中的首尾。记录章节或段落、精确行号、首尾文本、文件哈希、缺章及异常跳转。
3. 终点必须是可描述的剧情封口。不得为了补全悬念越界读取下一阶段，也不得把下一包事实倒灌进当前事件。

## 2. 冻结事件蓝图与原文包

1. 按用户指定数量拟定事件；用户未指定时，以每条能形成独立冲突、证据变化或可行动停止点为准，不为凑数拆分。若用户指定“20—60条”，蓝图冻结后必须位于该区间。
2. 每条蓝图至少记录：事件号、标题、阶段、原文范围、核心事实、冲突／未知项、安全校正、上一事件与下一事件边界。
3. 把连续原文切成不重叠、无空洞的包。每包给出精确首尾行和事件范围；单包必须明显低于执行代理的上下文上限，并为事件模板、规则和输出预留空间。长包继续细分，不让代理自行猜边界。
4. 先验证包的并集恰好覆盖阶段原文，交集为空；再冻结来源台账。任何缺章、重复标题或串章污染均显式登记，禁止补造。

## 3. 分包精读与事件草稿

若用户要求子代理：每个代理只读分配的原文包、冻结蓝图、相邻事件标题和一个既有事件样板；不得阅读下一包来补答案。代理只写自己的草稿文件，避免并发修改同一源码。

每条事件保持项目既有 EJS 门控和字段格式，至少包含玩家主权、阶段、地点、前置、参与者、默认走向、紧迫度、幕后停止点、变形／完成／取消条件、结果影响、系统提示及下一事件四字段。默认走向字数服从用户约束；未指定时按项目既有预算。最后一条只停在冻结终点，不虚构下一事件。

原作既定行为只可作为因果参考，林恩的对白、主动动作、决定、判断、心理与记忆仍由玩家独占。年龄、身份或有效同意能力未确认者不进入性或恋爱路线；伤害、胁迫、失能、污染与依赖保留其后果和问责，不改写成奖励或同意。

主代理逐包检查：事实是否被本包原文支持、默认走向是否停在玩家可行动点、完成条件是否没有偷结算、下一引入是否只泄露预兆、相邻包是否重复或断裂。蓝图与原文冲突时保留原文证据和玩家主权，并在编辑台账记录裁决。

## 4. 事件后再编写概念

事件全部冻结并通过结构校验后，才建立概念清单。按人物／关系、地点／势力／历史、机制／物品／诅咒等互斥包分派；同时标记“新增”与“更新既有”，避免只新增同义条目而让旧事实过期。

概念正文无默认字数上限，以完备为优先。每条至少写类别、事实门槛、定义、来源、机制、限制与代价、未知项、禁止外推；需要时增加状态账、资源边界、运行边界或分支差异。来源使用事件号，不在运行正文暴露章节、总结名或制作版本。

概念逻辑编号和世界书内部 UID 是两套标识。新增前扫描所有事件与概念 UID；若顺延编号会碰撞，保留逻辑编号并分配独立高位 UID 区间，把映射写进注册表和 contract，禁止静默覆盖已有条目。

## 5. 同步三层总结

依据已复核事件与概念分别生成：阶段末大总结、覆盖本阶段的小总结组、阶段总结。三者都以事件号为事实锚点，区分已确认、条件分支、失败态、未知项和下一阶段封口，并同步年龄和玩家主权口径。总结是编辑权威，不得在运行正文出现“大总结”“小总结”“阶段几”等元数据。

## 6. 克隆、集成与验收

1. 在目标路径不存在且旧版哈希已记录后克隆旧版；只改新版本。迁移版本号、事件终点、阶段数组、路由、schema、初始变量、mainline、状态栏桥接、worldbook、concept registry、contract、manifest、profile、README 和 host acceptance。
2. 用导入／同步脚本从冻结草稿生成 `src/`；不手改 `dist/`。为事件连续性、每条字段、字数、禁用元数据、玩家主权、UID 唯一性、桥接数量、终点无后继和概念引用增加确定性断言。
3. 运行项目规定的 `npm run check`，核对产物哈希、条目数、事件数、概念数及旧版哈希未变。离线通过只证明构建契约；真实 SillyTavern 导入、新聊天、生成、MVU、状态栏与持久化需单独授权和证据，不得写成已验收。
