# 添加新事件工作流（如 E13）

目标：新增一个事件锚点并接入常驻衔接链、详情窗口、状态栏按钮与验证器。**先读目标版本的 `AGENTS.md` 与 `创作规划.yaml`**；旧版本目录与产物不得改动。

## 1. 生成事件文件

```powershell
node scripts/add-event.mjs <版本目录> <E13> <事件标题>
```

脚本会：

- 在 `<版本目录>/src/events/` 生成 `E13_事件标题.md`（含 EJS 门槛、完整分支标题、字段模板、下一事件引入段）；
- 输出需要粘贴到 mainline.md / status.html / schema.js / initial_variables.json / worldbook.json / validate.mjs 的插入片段清单。

先用 `--dry-run` 预览，确认后再正式生成。

## 2. 填写事件内容

按模板填写：阶段、地点、前置条件、参与者与动机、默认走向、紧迫度、幕后停止点、变形条件、**完成条件、取消条件**、结果影响、系统提示；再写「下一事件引入（E14·待定）」的触发时机/剧情引子/预兆写法/承接因果。完成条件必须给出“什么才算真正收束”的硬标准（例：E03 仅猪头魔跑路不算完成，须血婴整容处置完成并形成稳定结果）。

## 3. 同步常驻链（mainline.md）

- `ctx` 数组追加 `{ id: 'E13', title: '...', line: '因果摘要' }`；
- 新增桥段 EJS 块（前一事件→E13，以及 E13→后一事件）；
- 若 E13 接在 E12 之后：E12 需要补「下一事件引入」段，并把“E12收束后不设计续接”的行改为 E12→E13 因果行，E13 作为新的收束边界；
- 更新窗口说明文字中的事件数量（如有）。

## 4. 同步状态栏（status.html）

`BRIDGE_PAIRS` 追加对应行（from/to/标题/预兆方向/地点/紧迫度/期限）。

## 5. 同步 schema 与初始变量

- `src/scripts/schema.js` 的 `anchorTitles` 加 `E13: '标题'`；
- `src/initial_variables.json` 的 `事件.锚点状态` 加 `"E13": {"标题": "标题", "状态": "未触发", "收尾": false}`；
- 重新生成 `first_message.md` 的 initvar（与 initial_variables 深度一致，按项目现有脚本方式执行）。

## 6. 注册蓝灯（worldbook.json）

追加条目：`id = 300 + 序号`，comment `[事件]E13·标题`，keys 含 `E13 / 事件E13 / 标题关键词`，content_file 指向新事件文件，双防递归开启。

## 7. 更新验证器（validate.mjs）

- `bridgePairs` 数组加 `['E12','E13']`（及 E13 后续对）；
- 事件循环范围、`### E12→` 断言、E12 无引入段断言按新链调整；
- 若新增断言，按项目规范补 `ok()`。

## 8. 构建与基线

```powershell
npm run check
```

全绿后同步 README / AGENTS / host_acceptance 的检查项数、产物大小与 SHA-256；更新创作规划的事件锚点列表；旧版本目录不动。

## 9. 真机验收清单

- 新事件进行中：上下文窗口 ◆当前 指向新事件、详情窗口展开其完整详情、下一事件仅占位、桥段不渲染；
- 新事件收尾后：下一桥段渲染、下一事件进预兆后详情解锁；
- 状态栏按钮就绪/禁用与上述一致。
