# 《诡异药剂师》v0.3 AI接手指南

## 适用范围

本文件适用于`诡异药剂师_MVU_v0.3/`整个目录。该目录是完整可构建的`chara_card_v3 / 3.0`、MVU Zod角色卡工程，正式候选产物为`dist/诡异药剂师_v0.3.json`。

不要手改`dist/`。所有修改进入维护源码和配置，再运行构建。旧版v0.1、v0.2目录与产物必须保持不变。

## 权威顺序

1. 用户当前明确要求。
2. `创作规划.yaml`。
3. `contract.json`。
4. `manifest.json`。
5. `profile.json`。
6. `src/`维护源码。
7. `dist/`生成候选产物。

内容范围变化先更新`创作规划.yaml`，结构要求同步到`contract.json`，文件映射和版本同步到`manifest.json`。

## 最高目标与叙事主权

- 最终目标是逐版本还原整部小说的世界观与人物，让玩家扮演20岁的林恩自由行动。
- v0.3新增资料范围截至第149章；v0.2已有内容继承，不专门清除其中的后期资料。
- 原作事件是世界自主运行的默认因果，不是玩家必须复刻的固定剧情。
- 玩家独占林恩的对白、主动动作、决定、意图、判断、记忆和内心。
- AI只能写环境、系统和NPC；需要林恩决定时停笔。
- 玩家明确写出的林恩行动、诊断和治疗方案按其陈述成立，不追加检定或隐藏失败。
- 未登场人物不能因世界书存在而瞬移、提前相识或获得未来知识。

## 主要角色

十名主要角色固定为：

- 左左
- 血锯
- 血衣女士
- 小小
- 人偶夫人
- 爱丽丝
- 黑弦月
- 泰坦头颅
- 巫神头颅
- 小宝贝

每人必须维护六个文件：`角色速览.md`、`基础信息.md`、`性格调色盘.md`、`三面性.md`、`多阶段人设.md`、`二次解释.md`。资料不足时写“未知/待后续补充”，不得依据名称或相似作品推断。

`src/worldbook.json`在运行时把每人的六个组件合并成一条`[角色]姓名`蓝灯。常驻`[角色索引]十人精简路由`只含姓名、别名、边界和解锁规则。

固定非恋爱且吸引始终为0：血锯、小小、爱丽丝、泰坦头颅、巫神头颅、小宝贝。左左在独立成年形态和心智明确前吸引也为0。

十名主要角色受保护，不会永久死亡或彻底退出。允许状态只有活动、受伤、失联、受困、休眠、暂离、敌对。

## 次要人物原则

只把具名、长期重复、拥有特殊设定的主角或女主升级为主要人物。特定大事件中的情报员024、噬心魔、械魔等归入魔人协会；黑蛾妖精玥玥等单次NPC归入药剂店来客。

次要人物只记录身份、可见特征、行为方式、与林恩的当轮关系和剧情功能，不建立独立调色盘，不加入MVU十人关系表。

## 世界书维护

世界书注册表是`src/worldbook.json`。条目前缀包括`[核心]`、`[角色索引]`、`[机制]`、`[势力]`、`[地点]`、`[角色]`、`[配角群像]`、`[事件]`、`[initvar]`、`[mvu_update]`。

每个新增或修改条目必须同时显式设置：

- `extensions.exclude_recursion: true`
- `extensions.prevent_recursion: true`

不要用`delay_until_recursion`代替。构建器默认值也保持两项为true，验证器必须同时检查源码和打包结果。

主要角色、势力、机制、地点和事件使用精确关键词。避免“女人”“医生”“神庙”等过宽词作为唯一触发条件。稳定数字ID不可重复。

事件蓝灯通过E01至E12稳定ID触发。预兆在本轮聊天和变量更新中写入事件ID，详细事件条目于下一轮加载。防递归开关不得关闭。

## 自主事件契约

阶段固定为：

- S0·药店接管期
- S1·怪物客户建立期
- S2·血衣与药剂风波期
- S3·魔人协会冲突期
- S4·猎头者家庭与师徒归来期

事件状态固定为未触发、预兆、活跃、变形、完成、取消。同时只能有一条重大事件活跃或变形。

事件按时间、阶段、有效行动和因果条件启动，不要求林恩到场。林恩介入后按实际结果改写；原作因果失效时转为变形或取消，不回轨。

林恩缺席时只做有限幕后演算。主要角色即将遭遇不可逆结果时停在可介入危机。普通诊疗和原创日常不占重大事件位；只有长期影响进入待定队列。E12收束后不自动设计第149章以后的续接、循环或结局。

每个`src/events/`文件必须包含阶段、地点、前置条件、参与者与动机、默认走向、紧迫度、幕后停止点、变形条件、结果影响、系统提示。

## MVU整链

根变量精确为：

- `元数据`
- `世界`
- `林恩`
- `事件`
- `关系`
- `角色关系`
- `系统`

没有`病例`根。病例只作为当前场景与事件内容叙述。

`关系`固定十名主要角色。姓名被玩家主动提到时，只允许把`解锁`改为true；不得同步改变在场、位置、处境、数值、记忆或互动。实际接触后才填写关系资料。

林恩缺席时，角色对林恩的关系数值不自行变化，位置、伤势和事件处境可以变化。`角色关系`只记录有长期意义的角色对，不建立十人全矩阵。

任何字段变化必须沿整条链同步：

`src/initial_variables.json` → `src/scripts/schema.js` → `src/prompts/mvu_update_rules.md` → `src/prompts/mvu_output_format.md` → `src/ui/status.html` → `contract.json` → `tools/validate.mjs`

更新协议固定为`UpdateVariable.JSONPatch`。同轮更新独立工作，额外更新预设只是可选项。v0.3只保证新聊天，不迁移v0.2聊天。

## 状态栏兼容

`src/ui/status.html`是死界通用三页界面：当前状态、人物关系、世界事件。必须保留：

- 只显示已解锁人物。
- 未实际接触时只显示姓名与状态。
- 实际接触后显示数值条、文字判断和详情。
- 显示唯一活跃事件、一个近期预兆和最近结果。
- 轻微魂灯呼吸、蓝光和紧急动效。
- `prefers-reduced-motion`。
- 页签键盘操作和移动端布局。
- 安全文本渲染，不使用`innerHTML`或`eval`。

真实宿主曾出现状态栏先于MVU接口可见的误报。必须保留双路径读取：

1. 当前或父窗口的`Mvu.getMvuData`。
2. 宿主`SillyTavern`聊天消息的`message.variables[swipe_id]`回退。

状态栏只读取已有变量，不建立第二套状态源，也不强制依赖iframe内的`waitGlobalInitialized`。
