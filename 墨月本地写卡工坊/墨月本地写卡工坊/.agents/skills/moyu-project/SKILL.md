# 墨月项目统筹

## 先读什么

1. 当前角色卡的 `src/<角色卡名>/项目状态.md` 和 `创作台.md`；不存在则说明是新项目。
2. `../../../必读/01_大白话拆解与项目推进.md`。
3. 只有确定第一个专项后，才读取那个专项的 Skill。

## 工作流程

1. 用用户原话概括目标，并明确当前理解可能存在的歧义；不替用户补成另一种作品。
2. 区分已确认事实、作者倾向、未知留白和互相冲突的说法。模糊词先追问实际表现，不直接映射成专业模块或成品。
3. 把需求拆成人物、世界书、规则、开场白、MVU、前端、EJS、脚本、检查与打包等专项。
4. 只展示用户当前需要知道的短路线；完整任务写进 `项目状态.md`。
5. 进入第一个专项。完成并验证后更新状态，再继续下一项。

## 小白沟通

- 不要求用户先整理栏目。允许一次性倾倒不通顺、不完整的全部想法。
- 用户材料太少时，给一个能够继续描述的大致方向；可以集中追问一至三个紧密相关的关键缺口，不使用专业问卷。
- 大白话解析属于当前秋青子的理解过程，不虚构第二个负责创作的 AI。
- 整理需求不等于授权直出主角。先反馈理解、分类和缺口，方向确认后才进入人物专项形成正式内容。
- 不把技术选型甩给用户。先根据酒馆环境判断可行方案，只让用户决定体验差异。
- 不因为任务很大而一次生成全部模块；也不因为信息不完整而强迫用户填满角色卡。

## 项目边界

- 一个角色卡一个 `src/<角色卡名>/`，不要把多张卡混在同一状态文件中。
- 默认只读当前角色卡。要参考其他项目时先说明原因和范围。
- `创作台.md` 是作者原始工作文件。默认只读，不能为了“整理得更漂亮”覆盖作者原文。
- 计划不是工件。用户确认方向或明确要求直接实施后，才调用专项修改正式文件。
