# 酒馆前端

## 必须读取

1. `../../../知识库/写卡知识库/自查/前端美化自查.txt`。
2. 涉及 MVU 状态栏时读取 `../../../知识库/写卡知识库/自查/MVU前端状态栏自查.txt` 和当前角色卡 `schema.ts`。
3. 查接口时读取 `../../../知识库/写卡知识库/酒馆助手接口/00_索引_先看这个.txt`，再只打开对应分类。
4. 以 `../../../初始模板/前端界面/` 和当前角色卡 `界面/` 为工程结构依据。

## 从大白话到界面

- 先把用户说的“想看到什么、怎么操作、什么情况下变化”转换成数据来源、显示区域和交互结果。
- 明显超出酒馆 iframe 能力或失败率高的效果，直接用白话说明限制和可替代方案。
- 图片需要可访问 URL 或随工程可打包的资源；不要假装本地路径能被其他玩家访问。
- 方案确认后再写代码。用户不需要先写专业前端提示词。

## 实现边界

- 用户可见界面全面禁止 Emoji，不把 Emoji 当装饰、按钮图标、状态标记或占位插图。
- 图标优先使用语义明确的内联 SVG，并统一 viewBox、描边粗细、尺寸和颜色继承；已有一致的项目 SVG 时优先复用。
- 不从参考界面复制 Emoji；纯文字已经足够表达动作时不强行增加图标。
- `index.html` 只保留静态 body 容器；代码和样式由 TypeScript/Vue 导入。
- 优先复用现有 Vue、Pinia、Zod、VueUse 和项目工具，不新增无必要依赖。
- MVU 前端使用 `defineMvuDataStore` 和 `schema.ts`，并等待框架与 `stat_data` 初始化。
- iframe 中避免 `vh`、横向溢出和脱离文档流的主体布局。
- 处理加载、空数据、错误和卸载；不要让 watch 形成写回循环。

## 文案与验收

用户可见界面只保留对象名称、操作、必要状态和错误。禁止用工程说明填页面。构建、数据行为、窄屏布局和最终视觉分别验收；没有实际看过酒馆画面时，不声称视觉通过。
