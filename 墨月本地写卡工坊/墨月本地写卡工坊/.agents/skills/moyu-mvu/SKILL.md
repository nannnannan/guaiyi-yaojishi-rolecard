# MVU

## 必须读取

- `../../../知识库/写卡知识库/MVU/MVU_ZOD指南.txt`。
- 编写代码或读取 MVU 数据时读取 `../../../知识库/写卡知识库/酒馆助手接口/16_MVU变量框架.txt`。
- 进入对应阶段时，只读取 `../../../知识库/墨月写卡方法/MVU/` 下同名条目。
- 需要审查时读取 `../../../知识库/写卡知识库/自查/MVU自查.txt`。

## 真实顺序

1. 用大白话讨论玩法，筛掉不会被规则、界面或脚本使用的变量。
2. 完成初始变量设计与 `initvar.yaml`。
3. 根据初始变量讨论并完成变量更新规则。
4. 使用前两部分编写纯 `schema.ts`；本地工程的 Schema 不含注册副作用。
5. 生成变量结构注册脚本、变量列表和固定输出。
6. 运行 Schema 与初始值检查，修正字段、类型和默认值不一致。
7. 状态栏、EJS 或其他脚本再消费这套已经稳定的变量。

不要在一次对话里跳过讨论直接同时创造所有工件。复杂 MVU 必须按阶段落地；已完成文件由后续阶段直接读取，不要求用户来回复制。

## 代码边界

- 使用 Zod 4，保持 `Schema.parse(Schema.parse(input))` 幂等。
- 对象优先于依赖数组下标的结构；只在玩法真的需要时增加限制和默认值。
- MVU 数据位于消息楼层变量的 `stat_data`。
- 前端或脚本读取变量时以本地 `schema.ts` 校验，不凭字符串路径猜类型。
- 最终变量文件位于当前角色卡的 `schema.ts`、`世界书/变量/` 和 `脚本/变量结构/`。
