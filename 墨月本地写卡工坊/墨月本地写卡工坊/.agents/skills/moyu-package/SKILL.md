# 检查与打包

## 原则

- 源文件是事实，`dist/`、JSON 和 PNG 是生成物。
- 使用 `tavern_sync.mjs` 和项目构建命令，不手写二进制元数据。
- 没有头像时可以导出 JSON，但不能声称已生成最终 PNG。
- 打包成功只证明结构可以生成，不证明酒馆运行、模型效果和视觉效果已经通过。

## 检查顺序

1. 读取当前项目 `项目状态.md` 与 `index.yaml`，确认目标角色卡。
2. 检查第一条消息、世界书、脚本、界面和扩展字段引用的文件是否存在。
3. 有 MVU 时检查 `schema.ts`、initvar、变量更新规则和消费端字段一致。
4. 有 EJS 时检查语法、默认分支和条目位置。
5. 对 TypeScript/Vue 运行定向类型或构建检查。
6. 使用同步脚本生成 JSON/PNG，并回读角色卡关键字段和内嵌世界书。
7. 需要酒馆实测时，明确区分自动检查与用户/浏览器验收。

不要为通过检查而删除未知扩展字段或改写用户导入的第三方脚本。发现不属于本项目生成的内容时，保留并报告来源边界。
