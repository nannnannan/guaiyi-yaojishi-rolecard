# EJS单条目多阶段人设设计与静态验收

更新时间：2026-08-26

## 一、结论

EJS基础版已经收缩为一个明确用途：一个角色的一份多阶段人设。正式流程由两个互斥使用的条目组成：

1. `🧭 EJS·多阶段人设设计`：聊天、核对变量、讨论阶段、重新收集最新材料并形成自足创作提示词。
2. `⚙️ EJS·多阶段人设创作`：只把一份完整提示词编译成一个EJS代码块和一个世界书配置代码块。

最终世界书是启用的蓝灯常驻条目，放在角色定义之后。全部阶段正文直接存在同一个EJS条目中，不使用旧版的控制器、`getwi`和若干禁用阶段条目。

## 二、核验来源与采用事实

- `写卡知识库/EJS/EJS基础语法.txt`
- `写卡知识库/EJS/EJS变量与输出.txt`
- `写卡知识库/EJS/EJS多阶段人设.txt`
- `新建文件夹/EJS使用/EJS实战指南_2026_ZOD版.md`
- `https://github.com/zonde306/ST-Prompt-Template`及其当前`docs/features.md`、`docs/reference_cn.md`
- `https://ejs.co/`

采用的当前事实：

- 世界书正文会在发送前处理EJS标签，标签外的命中分支文本成为实际提示词。
- MVU读取路径必须使用`getvar('stat_data.完整路径', { defaults: 初始值 })`。
- 标准`if / else if / else`可以在一个条目内直接选择文本，不需要调用其他条目。
- `<%_ ... _%>`可控制代码块与周围空白；`<%# ... %>`是不会进入输出的EJS注释。
- `<#escape-ejs>...<#/escape-ejs>`会保护范围内的EJS分隔符，使写卡提示词中的教学骨架和聊天回复中的待复制代码不被当前扩展提前执行。
- 蓝灯常驻属于世界书配置，不需要在EJS正文中添加激活装饰器。

旧教程中的“蓝灯控制器 + 多个禁用阶段条目 + `await getwi()`”只是一种历史实现，不是平台强制结构。本次主动删除它，因为用户明确不希望纯输出版本调用禁用模块。

## 三、设计边界

- 一次只讨论、编译一个角色；多个角色必须分轮完成并在轮次之间隐藏全部楼层。
- 阶段设计只使用现有initvar和更新规则，不在EJS中新增、修复或写回变量。
- 默认使用一个主阶段变量；只有组合仍能完整枚举时才允许极少量辅助变量。
- 动态对象、列表、聊天扫描、随机值、日期解析、外部条目状态和任意JavaScript表达式不在基础版范围内。
- 普通人物生境保存稳定人设；EJS只保存随阶段变化的差异，防止每个分支复制完整角色导致注意力浪费与内容漂移。
- 成品禁用`getwi`、`activewi`、变量写入、注入、正则、聊天读取、装饰器、外部脚本与网络请求。

## 四、最终保险与上下文隔离

设计条目在待定方案确认后，必须重新索取最新完整initvar和MVU变量更新规则。最后一次材料是唯一事实来源，然后重新核对路径、类型、默认值、范围、允许值和分支覆盖，才能形成最终创作提示词。

两个EJS条目都明确：一个角色完成后不在同一上下文继续第二个角色。除此之外，项目内全部正式条目均已增加统一规则：完成最终交付时，最后一句提醒用户保存结果并隐藏本次使用该条目产生的全部楼层；讨论阶段不会提前发送该句。

## 五、静态模拟

### 正常路径：单数值变量

输入提供一个角色、完整initvar、完整更新规则、稳定人物生境和三个阶段构想。设计条目先筛除稳定人设重复，建立低、中、高三段互斥边界；用户确认后重新提交最新变量文件，路径与默认值一致，输出唯一创作提示词。创作条目生成一条有最终`else`的EJS条件链和一份蓝灯配置。路径成立。

### 正常路径：固定选项变量

输入提供一个固定枚举关系状态。设计条目逐项把所有允许值分配到阶段，并指定与初始值对应的安全回退。创作条目使用严格相等和最终`else`，不进行字符串转换。路径成立。

### 多角色输入

用户同时提交两个角色。设计条目不分析第二个角色，只要求选择本轮唯一角色；创作提示词完成后停止并提醒隐藏全部楼层。不会把两个角色塞入同一EJS条目。

### 缺少合适变量

用户要求阶段切换，但现有initvar只有界面显示字段，更新规则也不会维护角色阶段。设计条目停止，让用户返回MVU设计链，而不是创建隐藏变量或用聊天关键词代替。

### 条件组合爆炸

用户要求多个数值、动态列表和事件时间共同决定阶段。基础版判定无法可靠穷尽，要求简化为一个主变量或改用其他环境，不输出脆弱条件树。

### 创作输入不完整

创作条目收到散乱聊天、多个角色或仍有待确认项时，只报告第一个阻断点并退回设计条目，不生成半成品代码。
