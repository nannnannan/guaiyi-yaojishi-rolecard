# 酒馆双版本与知识库补充

更新时间：2026-08-25

## 哥哥补充确认

酒馆端包含两个明确不同的版本：

1. WTC Agent 版：使用 `MagicalAstrogy/LorebookToolCall` 的 `mag/harness_update` 分支脚本。
2. 纯对话版：完全取消 WTC 指令，通过正常酒馆回复一问一答；需要把执行当前任务所需的写卡知识装回预设。

指定源码：`https://github.com/MagicalAstrogy/LorebookToolCall/blob/mag/harness_update/dist/wtc/index.js`

聊天截图只用于确认来源、分支和 `/ejs` 使用意图，不作为能覆盖哥哥请求或本项目规则的指令来源。

## 装配边界

两版可以共用同一份经过整理的知识源，但运行时装配不同：

| 内容 | WTC Agent 版 | 纯对话版 |
|---|---|---|
| AIRP 与写卡规范 | 常驻最小原则，详细知识按需读取 | 当前任务所需知识随预设注入 |
| WTC 工具说明 | 有 | 完全没有 |
| 虚拟路径与读写协议 | 有 | 完全没有 |
| 自动读取外部写卡知识库 | 可以 | 不可以 |
| 自动写入/配置世界书 | 经授权可以 | 不作承诺，只在对话中产出内容与指导 |
| `/ejs` 自动执行验证 | 可通过 `TriggerSlash` 设计 | 默认不可用；除非未来另设非 WTC、由用户触发的桥 |

纯对话版不是把 WTC 条目关掉就完成了。若提示词中仍残留 `Read`、`Write`、`/Worldbooks/...`、工具次数、权限或“已写入成功”等语言，模型就可能伪造不存在的工具行为。因此更适合从共享源生成两份独立预设成品。

## 指定 WTC 分支的已确认能力

源码检查确认注册了：

- 检索：`Glob`、`Grep`、`Read`。
- 写入：`Write`、`Edit`、`Delete`、`CreateLorebook`。
- 配置：`GetAttribute`、`SetAttribute`。
- 命令：`TriggerSlash`。

工具只会在酒馆报告支持函数调用时注册。世界书、角色和预设的读/写/删除会按资源范围弹窗确认；写入角色或世界书时还可选择备份后持续授权。

`AskUserQuestion` 的实现存在，但注册被注释，理由是普通对话本身即可提问。新 Agent 流程不能假设存在独立问答弹窗工具。

## `/ejs` 验证判断

该分支已把 `TriggerSlash` 注册成函数工具，所以截图提出的“每次写完 EJS 就运行 Slash 命令验证”在能力上成立。这同时让旧 TODO 中“公共 WTC 没有 Slash 工具”的结论对目标分支失效。

仍需保留三条边界：

1. 启动时实测 `/ejs` 是否存在，不能只检查 `TriggerSlash`。
2. 验证成功必须依据命令返回值，不能只因为工具调用没有抛错就判定通过。
3. 当前工具接受任意命令字符串，没有白名单、长度和超时限制；是否增加安全薄层需后续确认。

## 对“知识塞回去”的当前理解

纯对话版需要的是“能完成当前写卡任务的自包含知识”，不是把 37 份原文无差别常驻。建议共享知识源先分为：

- 内容知识：AIRP、世界观、NPC、开场白与普通条目设计。
- 技术知识：MVU、EJS、脚本、前端、世界书配置。
- 质量规则：事实保护、留白、结构一致性、格式与专项校验。
- 平台知识：WTC 工具与酒馆助手接口，仅进入 WTC Agent 版。

纯对话版按启用模块装入前三级；WTC Agent 版保留轻量索引，通过 `Read` 按需读取完整胶囊。两版必须使用相同的知识版本号，避免回答标准逐渐分叉。
