# 人物生境条目设计

更新时间：2026-08-25

## 当前基线

人物生境区固定由六个条目组成：一个可选的前置分流入口、四个相互独立的写作专项和一个可选的实测回流入口。

1. `人设起点·原始构想整理与分流（可选）`
2. `人物生境·基础信息`
3. `人物生境·生活结构`
4. `人物生境·人物性情`
5. `人物生境·场景表达`
6. `人设实测·结果分析与回流（可选）`

第一个和第六个条目都不属于人物生境正文的组成部分，也不是所有用户的必经步骤。已有明确思路的用户可以直接携带自己的材料进入任意专项；四个专项不得承接、引用或依赖第一个条目的状态。

最终人物生境的统一成稿属于后续共享成稿功能，不在这六个条目中增设伪模块，也不额外增加第七个人设模块。

六个条目共同形成可重复进入的闭环：

```text
混乱构想
→ 首次分流
→ 四个专项分别形成最小人物生境
→ 组合后放入干净的空角色卡实测
→ 实测诊断与回流
→ 返回需要修订的专项
→ 再次实测
```

## 四个专项共同的完成标准

四个专项都通过与用户持续对话逐步消化当前材料，但“持续对话”不等于要求用户不断增加内容。人物生境追求的是能够支持人物继续生成的最小环境，不是未经实测便把人设写满。

每个专项必须主动判断当前模块是否已经足够。满足以下条件时，应明确告诉用户“当前模块的基础结构已经完成”，停止继续索取材料：

- 当前模块已经能够承担其AIRP职责。
- 会实质改变结果的矛盾与歧义已经由用户决定，或者明确留白。
- 继续追问只能增加同义说明、一次性场景、固定反应或未经用户构想的新内容。
- 剩余不确定之处需要观察模型实际演绎，而不是继续在纸面上推测。

四个专项都要说明这套完成观，但不得要求用户每完成一个专项便立刻测试。用户先完成自己实际需要的部分并组成整套人物生境，再放入干净的空角色卡中进行统一实测。没有独立必要的生活结构可以并入基础信息；没有新内容的场景表达可以省略，因此“完成四个专项”不等于最终必须存在四个等长标签。

实测以后，用户可以携带以下任一材料进入第六个条目：

- 一段或多段AIRP实际回复正文。
- 对人物反应的自然语言感受，不要求专业术语或完整分析。
- 已经明确感觉缺少、过重、重复或偏离的部分。

第六个条目负责从实测证据中判断问题更可能来自基础信息、生活结构、人物性情、场景表达，还是根本不属于长期人设；随后将问题和有效材料重新分流到对应专项。它不直接重写整套人设，也不能为了修复一段偶然输出便给人物增加固定答案。

## 已完成条目

正式条目文件：`条目/人物生境/🧭_人设起点-原始构想整理与分流.txt`

状态：第一版正式正文已获哥哥确认，尚未装入酒馆预设。

入口条目没有为节省token而删减职责。它已经完整处理接收、分类、材料不足、代码块交付、分流和停止；入口阶段刻意不内置人物示例，是为了避免在用户第一次倾倒构想以前植入角色内容。

### 条目职责

- 先让用户一次性倾倒脑中已经存在的全部构想，不要求顺序、格式、通顺或完整。
- 不使用调色盘问题库，不以固定问题、示例或选项引导人物扩写。
- 只将用户亲自写出或明确确认的材料分为基础信息、生活结构、人物性情、场景表达、长期人设外材料和待归类材料。
- 材料不足时，每轮只请求一个宽方向的自由书写，不提出具体问题。
- 至少一个专项能够在不替用户选择人物方向的前提下继续工作时，输出材料包和精确去向并停止。
- 提醒用户将材料保存到本地，隐藏探索楼层，再把对应材料带入专项。

### 标签与显示合同

中间材料固定使用以下标签，避免与最终人物生境成品混淆：

- `<人物生境_基础信息材料>`
- `<人物生境_生活结构材料>`
- `<人物生境_人物性情材料>`
- `<人物生境_场景表达材料>`
- `<人物生境_长期人设外材料>`
- `<人物生境_待归类材料>`

每个非空材料包使用一个独立代码块，供用户一键复制。说明、分类理由、去向和保存提醒只能位于代码块外。空分类连同标签一起省略。

这些标签是写作过程中的中间材料标签，不得写入最终人物世界书。最终成品仍按 AIRP 教程使用实际角色名与内容类型组成的标签。

### 四个专项与实测回流条目

以下第一版正式正文已经建立，均未装入酒馆预设：

- `条目/人物生境/🪪_人物生境-基础信息.txt`
- `条目/人物生境/🏠_人物生境-生活结构.txt`
- `条目/人物生境/🫀_人物生境-人物性情.txt`
- `条目/人物生境/🎭_人物生境-场景表达.txt`
- `条目/人物生境/🧪_人设实测-结果分析与回流.txt`

四个专项都可以被用户直接开启，也可以接收首次分流材料或实测回流包。它们共同使用“宽进窄出”原则：当前主材料由本专项处理；理解当前内容所需的最少事实作为支撑锚点；明确属于别处的内容使用中间材料标签原样切出；暂时无法判断的材料由当前专项先保管，不在四个条目之间互相推诿。

每个专项持续与用户一问一答，但每轮只解决一个会改变结果的问题。用户明确留白即视为已经处理；专项达到最小生成条件后必须主动停止，不允许为了纸面完整继续填充。

四个专项先输出带 `_整理稿` 后缀的待确认标签。用户明确确认后，才输出实际角色名组成的最终AIRP标签。生活结构允许并入基础信息，场景表达允许整段省略。

实测回流条目使用以下标签，明确表示其中同时包含用户观察、输出证据与AI诊断假设，不能被专项直接当成新增人物事实：

- `<人物生境_基础信息回流>`
- `<人物生境_生活结构回流>`
- `<人物生境_人物性情回流>`
- `<人物生境_场景表达回流>`
- `<人物生境_长期人设外回流>`

第六条允许同时形成多个回流包，但只负责诊断与分流。用户返回修改时仍然一次只开启一个专项。

## 与旧版的明确差异

- 不复用 `自由创作助手` 的万能创作、YAML直出和自动世界书写入流程。
- 不复用 `角色基础` 的固定问题、角色示例、与使用者关系优先和下一条目强制串联。
- 不复用旧 `template_knowledge` 巨型问卷；当前条目只生产一份 `active_workshop_task` 合同。
- 不把教程、提问、检查、配置和最终成品塞进同一份交付物。

## 人物生境区的可选补充

核心六条目闭环保持不变。2026-08-25新增两项按需开启的补充能力，它们不属于所有用户的必经步骤，也不改变四个正式人物生境标签的组合顺序：

- `条目/人物生境/👥_NPC-轻量人物生境.txt`：允许根据用户几句话直接创作低token配角；使用人物生境的最小原则，但不把NPC扩写成主角档案。
- `条目/人物生境/👗_人物生境-穿衣风格.txt`：替代旧衣柜，只保存跨场景的穿衣选择倾向，不建立服装库存和固定套装。

NPC条目拥有用户明确授予的直接创作权限，这是对四个主角人物生境专项“只整理用户内容”的特例。穿衣风格仍遵守人物创作权，只负责教学、整理与压缩。

穿衣风格使用独立的可选过程标签：

- 首次分流：`<人物生境_穿衣风格材料>`
- 实测回流：`<人物生境_穿衣风格回流>`
- 整理稿：`<角色名_穿衣风格_整理稿>`
- 最终成品：`<角色名_穿衣风格>`

整套人设存在穿衣风格时，建议拼接顺序为：基础信息、穿衣风格、生活结构、人物性情、场景表达。没有独立穿衣作用时仍然省略，不改变核心四项的人设完成标准。
