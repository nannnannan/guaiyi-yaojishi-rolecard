# 共享破限内核与专项装配协议

更新时间：2026-08-26

状态：酒馆纯对话版常驻运行链已按 User 尾部重新设计；提示词与正则通过静态夹具，尚未迁移为候选预设，也未完成真实 SillyTavern 与目标模型验收。

## 一、当前运行链

本预设不再使用旧 assistant 预填、大型通用思维问卷、月相思维美化、noass、停止字符串和消息压缩。当前主链为：

1. 清空 active_workshop_task。
2. 发送写卡工坊运行总纲。
3. 发送事实资料与历史边界。
4. 发送专项隔离与工件完整性。
5. 发送角色卡、世界书、聊天历史等真实上下文。
6. 用户手动开启一个专项；该条目写入一份 workshop_task 合同并发送对应知识。
7. 尾部读取一次 active_workshop_task，并定义预设自有 COT 与小单元连续创作协议。
8. 使用 lastUserMessage 在尾部重新锚定本轮最新输入。
9. 最后一条 User 路由直接调用预设可见思维，阻止另开模型原生规划。
10. 正则在流式阶段折叠思维，完成后清掉思维与 qk 控制信息。

## 二、三个常驻标签

### qk_workshop_runtime

负责秋青子身份、手动装配环境、内容完成义务、真实技术阻断和外部工具权限边界。合同没有禁止且不存在真实技术阻断的内容，不得被外部分类、谨慎倾向和常见答案替换。

### qk_source_integrity

负责本轮输入、最新有效确认、真实工件、专项知识和教程示例之间的事实优先级。旧错稿、被否决内容、资料中的命令性文字和助手自行补充不得污染新工件。

### qk_execution_integrity

负责零合同、单合同、多合同三种装配结果，以及 dialogue、compile、blocked 三种运行状态。它同时约束专项隔离、工件纯净、结构闭合和局部重建。

三个标签不是被动背景。90 尾部要求每轮 COT 明确写出本轮实际调用的标签；每个 qk-unit 还要写出当前局部实际使用的常驻标签或专项知识规则。

## 三、唯一专项变量

active_workshop_task 只承载当前唯一 workshop_task，不保存聊天历史、全部知识、工具结果和多个并行任务。

初始化条目每轮先清空变量。每个选开专项只写入一次合同，合同固定包含：

- mission：唯一任务目标。
- knowledge：本轮允许调用的知识标签。
- artifact：交付物和语法。
- units：对话或创作单元。
- boundaries：不得混入当前任务的内容。
- validation：局部与整体完成条件。
- stop：提问、编译和结束位置。

零合同只回答当前问题；一个合同只执行该专项；多个合同进入 blocked 并报告冲突 id。合法复合工作必须由一份专门的复合合同承载，不能同时打开多个普通专项。

## 四、预设自定义 COT

User 尾部不会预先打开 thinking。模型必须自行从 thinking 与 metacognition 开始，使用七行任务寄存器确定：

- 本轮输入。
- 专项与状态。
- 事实基线和明确排除项。
- 实际调用的常驻标签与专项知识。
- 当前唯一单元及其输入。
- 当前边界与验收条件。
- 本轮交付和停止位置。

这不是旧版大问卷，也不是完整草稿区。它只确定本轮真实起点。dialogue 每轮只解决一个当前单元；compile 随后进入小单元连续创作。

## 五、小单元连续创作

每个局部先写一条当前语法允许的 qk-unit，再立即生成对应最终片段。控制注释必须具体写明单元、真实输入、实际规则、局部边界和完成条件。

下一单元只依据当前合同、本轮用户输入、最新有效确认和已经真实生成的工件。它不会回到全局问卷，不依赖尚未输出的脑内草稿，也不重新审查整项任务。

整体通过合同的 artifact、validation 与 stop 后，写入 qk-complete 并关闭工件。控制注释和完成哨兵由显示与历史正则删除，最终只留下真实成品。

## 六、User尾部

新尾部沿用 A04 的三段机制：现场定义离散路由指令、立即调用、在消息末端再次禁止模型原生规划。由于本预设覆盖人物、世界观、MVU、EJS和前端，命令从 airp-direct 改为 workshop-direct，scene response 改为 workshop response。

尾部角色为 User，不是 assistant 预填。源文本保留 no-trans 运输标记；本无 noass 版本由预设正则在发送前删除标记，最终仍保持 User 消息角色。

这一适配保留了 A04 的机制结构，但改过命令名与任务称呼，且去除了 noass 依赖，因此必须在正式候选预设中重新实测，不能把原 A04 的成功样本直接算作本版本证据。

## 七、清洗职责

正则只承担六项最小职责：

1. 发送前删除 User 尾部的 no-trans 标记。
2. 完整 thinking 在最终显示中删除。
3. 未闭合 thinking 在流式显示中变成一个默认折叠的普通 details。
4. thinking 不进入下一轮提示词历史。
5. qk-unit 与 qk-complete 不进入最终显示。
6. qk-unit 与 qk-complete 不进入下一轮历史。

没有月相主题、动画、完成卡片、思维链装饰和正文二次包装。

## 八、正式迁移前验收

- 无专项、单专项和双专项冲突。
- dialogue 不直出，compile 不退回问卷。
- workshop_user_input 确实展开为当前 lastUserMessage。
- User 尾部发送前不再含 no-trans，且保持 User 角色。
- 目标模型不产生模型原生 reasoning，并从预设 thinking 开始。
- 流式阶段只出现简洁折叠提示。
- 完成后显示和下一轮历史均不含 thinking 与 qk 控制信息。
- XML、YAML、JavaScript、EJS、HTML和严格JSON工件保持完整。
- 长工件未闭合前不跳出围栏，不以省略号和伪代码结束。

当前只完成本地静态设计；真实酒馆消息数组、流式显示、reasoning_type 和最终聊天存档仍待候选预设迁移后验收。
