# 用户信息写法教程

写在前面：这篇不是教你写角色。

角色怎么写，调色盘、混色、三面性、核心人格层，那些教程已经讲完了。

这篇讲的是`用户信息`。

也就是：你自己，在AI眼里是什么样的。

---

## 一：用户信息不是"人设"

先把这个概念掰清楚。

很多人一听"用户信息"就以为是给自己写一份角色卡。不是的。

角色卡是给AI演的。调色盘、衍生、三面性，全都是在告诉AI"这个角色应该怎么表现"。

用户信息不是给AI演的。

用户信息是给AI`读`的。

它的作用是：`补充用户输入内容，让AI扮演的角色做出正确的反应`。

为什么需要补充？

因为你打的字，永远比你脑子里想的少。

你输入"我揉了揉她的脸颊"，你脑子里想的是宠溺、喜欢、想逗她。

但AI不知道。

AI看到"揉脸颊"，它会去资料库里找"揉脸颊"最常见的语境。然后它可能找到的是：占有、挑衅、居高临下。

于是角色的反应变成了害怕、退缩、抗拒。

你想要的是她红着耳朵嘟囔"讨厌"，结果AI给你写了她僵住、眼神闪躲。

这不是角色写得不好。

这是AI`误读了你的行为`。

用户信息就是用来解决这个问题的。它告诉AI：这个用户是什么样的人，他做这个动作的时候，大概率是什么意思。

所以用户信息的本质是`提示词`，不是人设。

它不是在塑造一个角色，而是在`校准AI对用户行为的理解`。

---

## 二：没有用户信息会怎样

AI有一个很讨厌的习惯：`刻板印象补全`。

当用户输入不够完整的时候，AI会自动从资料库里调用最常见的解读来补全你的行为。

问题是，资料库里最常见的解读，往往是最`戏剧化`、最`冲突化`的那个。

举几个例子：

```text
你输入：我抓住了她的手腕。
你想的：着急，怕她走，想留住她。
AI理解：控制，强迫，压制。
角色反应：挣扎、恐惧、"你放开我"。
```

```text
你输入：我沉默了一会儿，没有说话。
你想的：在想怎么措辞，不想说错话。
AI理解：冷暴力，拒绝沟通，无视。
角色反应：不安、试探、"你是不是生气了"。
```

```text
你输入：我命令她坐下。
你想的：关心她站太久了，语气随意但在意。
AI理解：征服，支配，命令。
角色反应：屈服、反抗、或者变成奇怪的主仆play。
```

看出来了吗？

每一次AI都在往`最刺激`的方向补全。

因为AI的资料库里，"抓手腕"出现最多的场景就是强制和冲突。"沉默"出现最多的场景就是冷战。"命令"出现最多的场景就是支配。

这不是AI坏，是AI`没有别的参考`。

你不告诉它你是什么样的人，它就只能用刻板印象来猜。

用户信息就是那个"别的参考"。

你告诉AI：这个用户说话直接但不带恶意，他的"命令"其实是关心的表达方式，他沉默的时候是在思考不是在生气。

AI读到这些，再看到你的输入，就不会往最戏剧化的方向跑了。

它会想：哦，这个人抓手腕是因为着急，不是因为想控制。那角色的反应应该是被拉住后愣了一下，然后看到他着急的表情，心软了。

这就对了。

## 三：两种玩家，两种写法

AIRP的玩家大致分两种。

第一种：`抢话党`。

抢话党喜欢让AI扮演自己，让AI继续演一段剧情。用户输入可能是一大段，里面包含了自己角色的动作、对话、心理，甚至其他角色的反应。就像在写小说，然后让AI接着写下去。

第二种：`不抢话党`。

不抢话党只写自己角色做了什么、说了什么，然后等AI扮演的角色来回应。用户输入→AI回复，中间完全禁止AI扮演用户。

这两种玩法对用户信息的需求完全不同。

抢话党需要AI`演好你`。

不抢话党需要AI`读懂你`。

演好你，和读懂你，是两件事。

---

## 四：抢话党的用户信息怎么写

抢话党的用户信息，本质上就是在写一张`简化版角色卡`。

因为AI要扮演你，它需要知道你是什么样的人、怎么说话、怎么做事。

但注意，这不是完整的角色卡。你不需要写调色盘那么复杂的东西。

核心原则：`只写特化部分，不写常态部分。同时写禁止部分。`

### 基础信息

和角色卡的基础信息一样，简单填表。

```yaml
{{user}}基础信息:
  基本信息:
    性别: 男
    年龄: 18岁
    身份: 高三学生
  外貌特征:
    发色: 黑发
    穿着:
      校内: 校服，但穿得随意，领带经常歪
```

这部分没什么好说的。

但有一个关键点：`禁止部分`。

### 禁止部分

这是抢话党用户信息里最重要的东西之一。

你在写角色卡的时候，不需要写"禁止AI怎么演这个角色"，因为你写了调色盘和衍生，AI自然知道该怎么演。

但用户信息不一样。AI在扮演你的时候，会疯狂调用刻板印象来补全你没写的部分。你必须主动拦住它。

怎么拦？直接写在特征后面。

```text
白色短发（禁止频繁描写，仅初次见面的角色时可适当插入）
```

```text
身高一米八五（禁止在每次互动中都强调身高差，只在物理接触时自然体现）
```

```text
声音低沉（禁止每句对话都加"低沉的声音说道"，正常写对话即可）
```

为什么要这样写？

因为AI一旦知道你"白发"，它就会在每一段描写里都提你的白发。"白发少年微微一笑""他用修长的手指拨开额前的白发""月光下白发如银"——你会被自己的头发淹死。

`禁止部分`就是告诉AI：我知道我有这个特征，但你别老提。

### 性格部分

抢话党的性格写法，完整参考`调色盘`。

底色、主色调、点缀、衍生，该怎么写怎么写。因为AI要演你，它需要知道你的性格是什么质地。

但这里有一个抢话党专属的东西：`边界提示词`。

什么是边界？

就是你告诉AI：在某些特定时刻，允许产生新的性格衍生。

```text
边界：当剧情进入关键点或危急关头，允许产生新的性格衍生。
例如：平时沉默寡言的用户角色，在保护重要的人时可以爆发出从未展现过的果断和暴烈。
```

这条提示词的作用是：让AI在扮演你的时候，不会永远只用你写好的那几条衍生。

调色盘的衍生是你日常的样子。但人在极端情况下会变。你不可能把所有极端情况都写出来，所以你给AI一个`许可`：在关键时刻，你可以让我的角色做出超出日常的反应。

这就是`边界`。

它让AI扮演你的时候更加惊艳，而不是永远在安全区里打转。

### 抢话党的完整结构

```yaml
{{user}}基础信息:
  基本信息:
    姓名: （你的角色名）
    性别:
    年龄:
    身份:

  外貌特征:
    （只写特化部分，附带禁止说明）

  背景设定:
    （只写影响行为的关键经历）

性格调色盘:
  底色:
  主色调:
  点缀:
  （各衍生）

边界: 当剧情进入关键点或危急关头，允许产生新的性格衍生。
```

简单，但够用。

AI拿到这些，就能在扮演你的时候不跑偏，同时在关键时刻给你惊喜。

## 五：不抢话党的用户信息怎么写

这部分完全不一样。

不抢话党的AI`不扮演你`。AI只扮演角色，然后根据你的输入做出反应。

所以你不需要写调色盘。调色盘是给AI演的，AI不演你，写了也没用。

不抢话党的用户信息，核心是：`用户行为分析`。

什么意思？

你需要告诉AI的不是"我是什么性格"，而是"我做这些事的时候，是什么意思"。

回到开头的例子。

```text
你输入：我揉了揉她的脸颊。
```

如果你的用户信息里写了：

```text
{{user}}的肢体接触习惯：触碰是表达亲近和喜欢的方式，揉头、揉脸、拍肩都是宠溺和关心的表达，不带任何攻击性或占有欲。
```

AI读到这条，再看到"揉脸颊"，它就不会往"占有"上跑了。

它会想：这个人揉脸颊是宠溺，那角色应该感受到的是被宠爱，而不是被侵犯。

这就是不抢话党用户信息的核心逻辑：`你不是在描述自己，你是在给AI一份行为翻译手册`。

### 为什么不能写调色盘

因为调色盘是给AI`演绎`用的。

AI读到调色盘，它会想：好的，这个人底色是温柔，主色调是沉默和内敛，那我来演一个温柔沉默内敛的人。

但不抢话党不需要AI演你。你自己会写自己的行为。

如果你写了调色盘，AI反而会出问题。它会拿你的调色盘去`预判`你的行为，然后在角色的反应里提前植入对你性格的解读。

比如你的调色盘写了"底色：沉默"，然后你输入了一句很热情的话。AI会困惑：他不是沉默的吗？这句话不像他。然后角色的反应可能变成"她愣了一下，没想到他会说出这样的话"——但你根本没想表达反差，你就是正常说了句话。

所以不抢话党`不写调色盘`。

你写的是另一种东西。

### 基础设定

基础设定还是要写的。和抢话党一样，简单填表。

```yaml
{{user}}基础信息:
  基本信息:
    性别: 男
    年龄: 18岁
    身份: 高三学生，和角色同校
  外貌特征:
    发色: 黑发
    穿着:
      校内: 校服，穿得随意，领带经常歪
  背景设定:
    家庭背景:
      父母: 家里开厂的，家境好
      住处: 和角色家住对门
    关键经历:
      - 有记忆起就和角色在一起
  关系设定:
    与角色的关系:
      起点: 住对门，从小一起长大
      感情状态: 情侣
      互动方式: 被拍后脑勺也不躲，被整理衣领就站着让她弄
```

这部分的作用是让AI知道`你是谁`、`你和角色什么关系`。

但真正重要的是下面的部分。

### 行为翻译手册

这是不抢话党用户信息的核心。

你需要把自己的行为习惯拆开，告诉AI：当我做这个动作的时候，我的意思是什么。

具体怎么拆？从这几个维度：

**1. 肢体接触的含义**

```text
{{user}}的肢体接触:
  触碰方式: 揉头、揉脸、拍肩、拉手、搂肩
  含义: 全部是亲近和宠溺的表达，不带攻击性
  禁止误读: 不要将{{user}}的肢体接触理解为占有、控制或性暗示，除非{{user}}的输入中明确包含这些意图
```

**2. 语气和措辞的真实含义**

这是最容易被AI误读的部分。

```text
{{user}}的说话方式:
  命令语气: {{user}}说"坐下""过来""别动"时，不是在支配或征服，是关心的随意表达，语气像对很熟的人说话
  沉默: {{user}}不说话的时候是在思考措辞，不是冷暴力，不是生气，不是拒绝沟通
  简短回复: {{user}}回复"嗯""哦""好"不代表敷衍或不在意，是他的正常交流方式
  吐槽和损: {{user}}说"你傻啊""笨蛋"是亲昵的表达，不是侮辱
```

看到了吗？

每一条都在做同一件事：`把AI可能的错误解读拦住`。

AI看到"命令"会想到征服。你告诉它：不是征服，是关心。

AI看到"沉默"会想到冷暴力。你告诉它：不是冷暴力，是在想。

AI看到"笨蛋"会想到侮辱。你告诉它：不是侮辱，是亲昵。

这就是`行为翻译`。你在帮AI把你的行为从"刻板印象版本"翻译成"真实版本"。

**3. 情绪表达方式**

```text
{{user}}的情绪表达:
  开心时: 不会大笑或夸张表达，更多是嘴角微翘、多说两句话、主动靠近
  生气时: 不会吼叫或摔东西，会变得更沉默，说话更短，但不会离开
  难过时: 不会哭，会发呆，会做一些无意义的小动作比如转笔、看窗外
  紧张时: 会摸后脑勺，说话变快，偶尔结巴
  吃醋时: 不会直说，会突然变得话少，或者故意提起别的话题
```

这部分的作用是：当AI需要在正文里描写角色`对你的反应`时，它能准确判断你当前是什么情绪。

比如你输入"我看了她一眼，没说话"。

没有用户信息，AI可能理解成：他在审视她/他不满/他在冷处理。

有了用户信息，AI知道你"沉默是在思考"，那角色的反应就会变成：她注意到他在看自己，似乎在想什么，于是安静地等着。

反应完全不同。

**4. 与特定角色的互动模式**

如果你玩的角色比较固定，可以写你和这个角色之间的专属互动。

```text
{{user}}与鱼冰的互动模式:
  靠近时: 自然地凑过去，不会刻意保持距离，肢体接触频繁但随意
  被她念叨时: 不会反驳，站着听完，偶尔笑一下
  她生气时: 不会道歉也不会解释，会默默做一些她喜欢的事来哄
  她难过时: 不会说安慰的话，会直接把她拉过来，让她靠着自己
```

这些不是在写你的性格。

这些是在告诉AI：当我做了某个动作，角色应该怎么理解这个动作。

`靠近`不是入侵，是自然。`不反驳`不是认怂，是包容。`不道歉`不是冷漠，是用行动代替语言。`拉过来`不是强制，是保护。

你在给AI一副眼镜。戴上这副眼镜，AI看你的每一个动作都会是正确的颜色。

### 不抢话党的完整结构

```yaml
{{user}}基础信息:
  基本信息:
    （填表）
  外貌特征:
    （特化部分）
  背景设定:
    （影响行为的关键经历）
  关系设定:
    （和角色的关系）

{{user}}行为模式:
  肢体接触:
    （触碰方式和真实含义）
  说话方式:
    （语气、措辞的真实含义，禁止误读）
  情绪表达:
    （各种情绪下的具体表现）
  与（角色名）的互动模式:
    （专属互动习惯）
```

## 六：为什么这套写法有效

回到最开始说的那个问题。

AI为什么会误读你？

因为AI在处理你的输入时，有一个隐藏的步骤：`行为归因`。

你输入一个动作，AI不会直接拿这个动作去写角色反应。它会先给这个动作`归因`——这个人为什么做这个动作？他的动机是什么？

归因完了，才写角色反应。

问题就出在归因这一步。

没有用户信息的时候，AI的归因来源只有一个：`资料库里这个动作最常见的动机`。

"抓手腕"最常见的动机是控制 → 归因为控制 → 角色反应是抗拒。

"命令坐下"最常见的动机是支配 → 归因为支配 → 角色反应是屈服或反抗。

有了用户信息以后，AI的归因来源变成了两个：资料库 + 你的行为翻译手册。

而且你的行为翻译手册优先级更高，因为它是`针对这个具体用户`的信息，比资料库里的通用信息更精确。

"抓手腕" + "{{user}}的肢体接触是亲近表达" → 归因为着急和关心 → 角色反应是被拉住后心软。

"命令坐下" + "{{user}}的命令语气是关心的随意表达" → 归因为关心 → 角色反应是嘟囔着坐下来。

这就是用户信息的底层逻辑。

它不是在改变AI的行为。

它是在改变AI`理解你的方式`。

理解对了，反应自然就对了。

## 七：和调色盘体系的关系

用户信息在整个写卡体系里的位置是这样的：

```text
角色基础信息：角色是谁。
调色盘：角色是什么质地。
核心人格层：角色为什么会做决定。
三面性：角色在不同场景怎么运作。
混色：角色在同一瞬间里多种颜色怎么撞。
二次解释：作者按住AI的误读。
用户信息：按住AI对用户行为的误读。
```

注意最后两条。

`二次解释`是防止AI误读`角色`。

`用户信息`是防止AI误读`用户`。

它们做的是同一件事，只是方向不同。

二次解释告诉AI："这个角色的生气不是真的生气，是多种情绪溢出来的形状。"

用户信息告诉AI："这个用户的命令不是真的命令，是关心的表达方式。"

都是在拦住AI的`自动补全`。

所以用户信息本质上就是`用户版的二次解释`。

## 八：常见错误

### 错误一：把用户信息写成小说人设

```text
他是一个外表冷漠内心温柔的少年，有着不为人知的过去，
在月光下他的眼神总是带着一丝忧郁……
```

这是小说，不是提示词。AI读了只会学会用同样华丽的方式描写你，不会因此更理解你的行为。

用户信息要`干`。像说明书一样干。

```text
{{user}}沉默时是在思考，不是冷暴力。
{{user}}说话简短是习惯，不是敷衍。
```

这才是AI能用的东西。

### 错误二：不抢话党写了调色盘

前面说过了。不抢话党不需要调色盘。

你写了"底色：沉默"，AI就会拿这个标签去预判你的所有行为。你偶尔热情一次，AI反而觉得不对劲。

不抢话党写的是`行为翻译`，不是`性格定义`。

### 错误三：抢话党没写禁止部分

你写了"白发"，AI就会在每段描写里都提你的白发。你写了"声音好听"，AI就会在每句对话前都加"他用好听的声音说"。

特征后面必须跟`禁止说明`。告诉AI什么时候可以提，什么时候别提。

### 错误四：写了太多"我不是什么"

```text
{{user}}不是冷漠的人。
{{user}}不是控制欲强的人。
{{user}}不是会冷暴力的人。
```

这种写法有一个致命问题：AI读到"不是冷漠"，它脑子里第一个蹦出来的词就是`冷漠`。你越说不是什么，AI越会往那个方向想。

正确写法是直接写`是什么`：

```text
{{user}}表达关心的方式是行动而非语言。
{{user}}沉默时是在思考措辞。
{{user}}说话简短是因为习惯直接。
```

不要告诉AI你不是什么。告诉它你是什么。

### 错误五：用户信息写得比角色卡还长

用户信息不是主角。角色才是主角。

用户信息的token量应该控制在角色卡的`四分之一以下`。

写多了，AI的注意力会被你的用户信息抢走，反而影响角色的表现。

够用就行。核心行为翻译写清楚，剩下的让AI自己判断。

## 九：实操检查清单

写完用户信息以后，问自己这些问题：

```text
抢话党：
  AI能不能靠这些信息演出"像你"的角色？
  禁止部分写了吗？特征会不会被AI反复提起？
  边界写了吗？关键时刻AI能不能突破日常表现？

不抢话党：
  你最常被AI误读的行为，写进去了吗？
  每一条行为翻译，是不是都在说"我做这个的时候意思是什么"？
  有没有写成性格定义？如果有，删掉，改成行为翻译。
  有没有写"我不是什么"？如果有，改成"我是什么"。

通用：
  token量是不是控制在合理范围内？
  基础信息是不是只写了特化部分？
  有没有写成小说？如果读起来像文学作品，重写。
```

## 十：大白话总结

`角色卡`：告诉AI这个角色是什么样的。

`用户信息`：告诉AI这个用户是什么样的。

但这两个"是什么样的"，含义完全不同。

角色卡是给AI`演`的。AI要变成那个角色。

用户信息是给AI`读`的。AI要理解这个用户。

`抢话党`的用户信息接近简化版角色卡——基础信息、调色盘、禁止部分、边界。因为AI要演你。

`不抢话党`的用户信息是行为翻译手册——基础信息、肢体接触含义、语气真实含义、情绪表达方式、互动模式。因为AI要读懂你。

用户信息不是人设。

它是一副眼镜。

戴上这副眼镜，AI看你的每一个动作，都会是你想让它看到的那个意思。

不戴这副眼镜，AI就只能用刻板印象来猜。

猜对了是运气。

猜错了是常态。

所以，写用户信息。

不长，不难，但有用。
