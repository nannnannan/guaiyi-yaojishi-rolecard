## 2. EJS 实现地图

### 八角色六组件

- `src/worldbook.json` 以 ID 100/110/120/130/140/170/180/190 注册八名角色。姓名/别名命中蓝灯后，`tools/build.mjs` 按「角色速览→基础信息→性格调色盘→三面性→多阶段人设→二次解释」的固定顺序合并每人 6 个源文件。
- 组件内直接用 `getvar("stat_data.事件.锚点状态.E##.状态")` 读 MVU。登场门通常为 `!== "未触发"`，里程碑门为 `=== "完成"`；未登场分支只显示资料锁定占位。
- 这些组件不在构建时预计算；它们随蓝灯条目进入提示后，由 ST-Prompt-Template 在每轮生成前按当前 MVU 状态渲染。

### 事件介绍、蓝灯与常驻窗口

- E01–E20 以 ID 300–319 注册为事件蓝灯。状态为「未触发」时只输出标题与保密占位；其他状态才公开完整事件字段。
- `src/prompts/mainline.md` 常驻计算当前锚点，渲染当前 ±3 的一句话因果摘要，并得出当前 ±1 的 `detailWindow`。
- `tools/build.mjs` 在构建时把 20 个事件的详情部分并入常驻调度条目，再用 `detailWindow` 在运行时选择。事件文件末尾的「下一事件引入」不复制到详情窗口；19 对 Ei→Ei+1 即时衔接由 `mainline.md` 的常驻段单独负责。

### 概念、物品与特殊设定

- 52 条概念是独立世界书条目，全部 `constant: true`、`keys: []`，分为势力 9、场景 6、物品 14、特殊设定 9、能力 9、诅咒 5。
- 每条内部扫描 E01–E20：优先取「活跃/变形」，否则取近期预兆的前件，再否则取最近收束锚点；只有当概念的 `__evs` 与当前锚点距离不超过 3 时才输出概念正文。
- 原实现在 52 个同时常驻的条目中都顶层声明 `const __ids` / `let __cur` / `const __evs` / `const __on`，真机共享 EJS 编译作用域因此报重复声明。现已给 52/52 个源文件首行增加 `@@private`，由 ST-Prompt-Template 为整条自动包裹块作用域。真机复验时重复声明为 0。

## 3. 本轮确定修复

1. **开场事件漂移**：`initial_variables.json` 的权威初态是 E01完成、E02收尾活跃、E03未触发，但构建场景和常驻提示仍写 E01活跃。已同步 `创作规划.yaml`、`card_description.md`、`mvu_output_format.md`、`build.mjs` 并补验证断言。
2. **状态栏被当作代码块**：源 HTML 以 `<style>` 开头，酒馆助手 4.9.1 不会按可执行前端识别。现以 `<body>` 开头，使用 `data-wa-status-root` 稳定定位。
3. **旧楼层回滚最新 MVU**：原按钮从旧 iframe 读取整份快照，却写回 `latest`。现历史楼禁用；即使脚本强制去掉 `disabled` 并点击，处理器也拒绝写入。
4. **回退数据假启用**：原界面只看 MVU API 能力，没有已持久 `stat_data` 时仍会启用按钮，点击静默无响应。现拆分能力就绪与持久数据就绪，缺数据时明确禁用并显示原因。
5. **初始化时序**：`waitGlobalInitialized` 本身可能晚到。状态栏先等桥接函数出现，再等 Mvu，超时进入明确不可用态。
6. **写回没有真正落盘**：iframe 内 `replaceMvuData` 可以让当前界面看似更新，但重载后可能恢复旧值。现另通过父/顶层宿主的 `TavernHelper.setChatMessages`更新最新消息变量，再调用 `saveChat`。
7. **占位符污染模型历史**：新增 prompt-only 正则，将历史中的 `<StatusPlaceHolderImpl/>` 从发往 AI 的上下文移除，显示正则仍正常渲染状态栏。
8. **概念 EJS 作用域**：52 条概念统一 `@@private`，验证器逐条检查且模拟共享作用域编译。
